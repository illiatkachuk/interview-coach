# STATUS

## Що зроблено

MVP повністю готовий і перевірений. Проєкт лежить у `interview-coach/`,
встановлюється як пакет із консольною командою `interview-coach`.

**Команди CLI (click):**
- `new <тема>` — генерує задачу через Anthropic API (`-d easy|medium|hard`, `-l uk|en`), зберігає в SQLite, друкує умову;
- `submit <id_задачі> <файл.py>` — запускає розв'язок у subprocess (таймаут 15 c, `--timeout`), показує stdout/stderr, надсилає умову + код + результат запуску Claude і друкує вердикт/оцінку/фідбек;
- `history` (`-p <id>`) — список задач і спроб;
- `show <id>` — умова збереженої задачі.

**Модулі** (`src/interview_coach/`):
- `llm.py` — Anthropic SDK: генерація задачі та рев'ю розв'язку;
- `runner.py` — запуск розв'язку (`sys.executable`, таймаут, обрізання виводу до 20К символів);
- `db.py` — SQLite: таблиці `problems` та `attempts` (за замовчуванням `~/.interview-coach/history.db`);
- `config.py` — власний парсер `.env` (без залежності python-dotenv), шляхи, константи;
- `cli.py` — команди.

**Перевірки:**
- 32 тести, всі зелені (`pytest`): db, runner, llm (моки), CLI (CliRunner), wire-level інтеграція;
- повний e2e через реальний бінарник проти фейкового локального API-сервера: `new → submit → history → show` — усе працює, включно з реальним запуском розв'язку ДП-задачі.

## Ключові рішення і чому

1. **Модель `claude-opus-4-8` + `thinking: {"type": "adaptive"}`** — актуальний дефолт Anthropic API; `budget_tokens` на цій моделі вже не підтримується.
2. **Структуровані відповіді через `output_config.format` (json_schema)** замість парсингу вільного тексту — API гарантує валідний JSON, тож генерація задачі повертає строго `{title, statement}`, а фідбек — `{verdict, score, feedback}`. Це прибирає цілий клас помилок парсингу.
3. **`.env` парситься власною функцією `load_dotenv()`** (~15 рядків) — не тягну python-dotenv заради одного файлу. Наявні змінні оточення мають пріоритет над `.env`.
4. **Фідбек і умови за замовчуванням українською** (`-l en` для англійської) — ви пишете українською, тож це очевидний дефолт.
5. **Задача вимагає скрипт без stdin** (функція + демонстрація через `print`) — так `submit` може просто запустити файл і показати вивід Claude без інтерактивності.
6. **Спроба зберігається навіть якщо API впав** — запуск розв'язку не пропадає; в історії вона позначена «без фідбеку».
7. **Помилка відсутніх облікових даних оброблена окремо**: SDK кидає `TypeError` (не `APIError`), без обробки користувач бачив сирий traceback — знайшов це при smoke-тесті, виправив на чисте повідомлення з підказкою про `.env` (є тест).
8. **Тести не ходять у мережу**: юніт-тести мокають клієнт, а `test_integration.py` ганяє реальний SDK через `httpx.MockTransport` — перевіряє справжню серіалізацію запиту (model/thinking/output_config) і парсинг справжньої відповіді Messages API без сокетів. Це найцінніший шар тестів: він би зловив несумісність параметрів із версією SDK.

## На чому застрягав

1. **`ANTHROPIC_API_KEY` немає ні в оточенні, ні через `ant`-профіль** — живий запит до API не перевірявся. Код написаний під ключ у `.env` (див. `.env.example`); увесь wire-шлях перевірено фейковим сервером та MockTransport, тож із ключем має працювати без змін.
2. **Фонові listening-сокети в цьому середовищі не працюють**: фейковий HTTP-сервер, запущений як фоновий процес shell, створював сокет у стані `CLOSED` замість `LISTEN` (навіть поза сендбоксом) — перший варіант e2e падав по таймауту. Обхід: сервер у потоці батьківського Python-процесу, CLI — його subprocess (`scratchpad/e2e_driver.py`). Після цього e2e пройшов повністю. На звичайній машині це обмеження не відтворюється.

## Як запустити

```bash
cd interview-coach
source .venv/bin/activate        # venv уже створено, пакет встановлено
cp .env.example .env             # вписати свій ANTHROPIC_API_KEY
interview-coach new dynamic-programming
interview-coach submit 1 solution.py
interview-coach history
pytest                           # 32 passed
```
